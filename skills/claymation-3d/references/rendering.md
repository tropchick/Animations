# Рендер на CPU и проверка движения

Точка входа примера — `video/src/ClayPostalStreet.tsx`. Она использует тот же lockfile и webpack, что и другие ролики репозитория. Ссылка `video/src/clay-examples` ведёт к исходникам примеров. Выполняйте команды из `video/`. Для локального Chromium можно добавить `--browser-executable=/usr/bin/chromium`. В остальных случаях Remotion использует свой браузер.

```sh
npm ci
npm run studio:clay
npm run render:clay
npx remotion still src/ClayPostalStreet.tsx ClayPostalStreet out/portrait.jpg --frame=330 --jpeg-quality=95
npx remotion still src/ClayPostalStreet.tsx ClayPostalStreet out/walk-draft.png --frame=68 --scale=0.5 --props='{"quality":"draft","mode":"smooth","seed":23}'
```

**Два независимых регулятора.** Флаг `--scale` меняет размер файла. Параметр `quality` меняет геометрию куклы, разрешение карты тени и участие оптического прохода. Для постановки используйте `draft` и половинный размер. Для портрета изучите `final` в исходном разрешении. При нехватке памяти сначала оставьте один браузерный рабочий процесс (`--concurrency=1`), затем уменьшайте размеры цели. Замерьте отдельно холодный старт (сборка, создание карт) и серию соседних кадров с общей сценой.

**Бюджет сцены.** Геометрия поверхностей переиспользуется. Четыре карты нормалей запекаются при первом обращении, гребни пальцев не вычисляются для каждого пикселя каждого кадра. Уличные плитки собраны в instanced mesh с индивидуальными цветами и матрицами. Тонкие жгуты объединены по назначению. Удалённые здания используют укрупнённые формы. Одна направленная лампа строит карту теней. В финальном проходе есть буфер цвета и глубины размером с кадр. Общие принципы профилирования описаны в [threejs-performance](../../threejs-performance/SKILL.md).

**Как отбирать кадры.** Возьмите исходную позу, ходьбу с опорой на каждую ногу, первый взгляд на самолёт, встречу с ладонью и неподвижный портрет. Для проверки фликера дополнительно возьмите несколько последовательных кадров. Числа разностей на редкой раскадровке отражают ещё и наезд. Примените существующий скрипт к одинаково отмасштабированным кадрам в порядке времени.

```sh
python ../skills/animation-quality-gate/scripts/animation_contact_sheet.py \
  --frames out/wide.png out/passing.png out/reaction.png out/portrait.png \
  --out-image out/contact.jpg --out-report out/difference.json --cols 4
```

**Экспозиция.** При 30 FPS и 12 позах/с кадры 0–2 показывают позу 0, кадры 3–4 позу 1, кадры 5–7 позу 2. За 30 кадров получается ровно 12 поз. Деление на округлённое число кадров в одной позе нарушит этот темп. Кожа, радужка и рука выбирают одно значение времени; неподвижный seed детали определяет её форму. На неподвижной камере кадры 330 и 331 должны совпасть в режиме stop-motion. В плавном режиме поза вычисляется заново на каждом кадре. Проверяйте PNG в одном браузере и с одинаковыми настройками. Разные версии графического драйвера могут округлять пиксели по-разному.

**Приёмка.** Оцените силуэт у фона, контакт подошвы, крепление сумки и неподвижность отпечатка относительно носа. Просмотрите участок прохода машин и перехвата письма в реальном темпе. При изменениях геометрии и объектива переснимите те же кадры. [Результаты проверки демонстрации](review.md)
