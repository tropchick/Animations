# Сценарная обратная связь

Используй [общую базу канала](../../../channel-experience/README.md), которую читает video-idea-generator. При указанном пути работай с той же копией, что была у генератора идей. Связывай черновик с `ideas[].id`, а после выхода ролика с `published_videos[].id`. Оценки автора и статистика площадок уже имеют собственные поля в базе. Для спорных наблюдений и гипотез используй предусмотренные разделы.

У общей базы строгая схема. Детальную историю правок сценария храни в необязательном файле `script-feedback.json` рядом с активной копией базы. Начни с [шаблона событий](../templates/script-feedback.json). Если рабочая база или файл доступны только для чтения, верни записи для переноса. Приватную обратную связь и статистику сохраняй вне публичного Git.

## Запись и применение

1. Выдели стабильный `script_id` для сценария и при каждой правке увеличь `revision`. У действия пользователя должна быть дата и источник, например ссылка на комментарий или согласованная выдержка из брифа. Добавь `idea_id` и `published_video_id`, когда известны. Проверяй существование ID в активной базе.
2. Записывай конкретные принятые и отклонённые хуки, формулировки, предпочитаемую манеру речи, удачные структуры и причины правок. Укажи, относится ли решение к реплике, ролику, рубрике или всему каналу. Если пользователь промолчал либо причину пропустил, сохрани причину как `null` и воздержись от вывода о предпочтении. Явно сформулированное общее правило можно отдельно внести в `preferences` общей базы.
3. После публикации привяжи результат по `published_video_id`. Сами оценки внеси в `owner_result`, численные метрики в `metric_snapshots`. Сравнивай площадку, возраст ролика, окно измерений, длительность и источник данных. Удержание, тема, узнаваемость, обложка, визуальный ряд и условия выпуска могут меняться одновременно. Вывод о причине обозначай гипотезой и предложи сравнение, которое поможет её проверить.
4. При следующем сценарии ищи записи по выбранной идее, теме, формату и области применимости. Применяй явную свежую обратную связь и оценивай редакторские гипотезы с учётом их оснований. Совпадение по теме само по себе не делает приём подходящим. При отмене решения допиши событие `revision_note`, укажи ID пересмотренной записи и новую область решения.
5. Перед сохранением открой свежую версию файла, добавь событие с уникальным `id`, проверь ссылки и JSON, затем сохрани целиком. Если файл изменился параллельно, перечитай и объедини события по ID. Новый дубль комментария с тем же источником, версией, типом и предметом не добавляй.

Используй типы событий `hook_approved`, `hook_rejected`, `speech_preference`, `phrase_rejected`, `structure_approved`, `revision_note`, `publication_linked`. Для области выбери `line`, `script`, `series`, `channel`. Демо-событие из шаблона замени фактическими записями. Источник необходим для любой записи о решении автора. Связь с опубликованным видео сама по себе не даёт редакторской оценки.
