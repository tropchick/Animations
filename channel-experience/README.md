# База опыта Animations

[Рабочий файл](animations.json) содержит опыт одного канала. [Разбор роликов](analysis.md) связывает исходники, оценки владельца и редакторские гипотезы. Генератор идей и будущий `viral-scriptwriter` читают одну базу. Для другого канала начните с [пустого шаблона](templates/channel.json) и нового `channel_id`. Структура описана в [JSON Schema v1](schema.json).

## Как читать и обновлять

| Раздел | Что хранить |
| --- | --- |
| `published_videos` | Один объект на произведение и отдельные `publications` для известных площадок. `owner_result` хранит оценку автора. `duration_seconds` сопровождается `duration_basis`, чтобы отличать время исходного рендера от длины публикации. `sources` ссылается на файлы от корня репозитория и внешние источники. |
| `metric_snapshots` | Численные данные конкретной публикации с датой снимка, окном измерений и происхождением. Повторные снимки позволяют сравнивать сопоставимый возраст роликов и отслеживать изменения. |
| `ideas` | Показанные концепции со стабильными ID, направлением поиска и структурным отпечатком. Пять полей отпечатка описывают тему, правило, развитие, визуальный приём и развязку. |
| `preferences` | Только явно высказанные предпочтения, требования и ограничения со ссылкой на формулировку пользователя. |
| `observations` | Проверяемые сопоставления из материалов и результатов с ID роликов. |
| `hypotheses` | Возможные объяснения с признаком проверки, основаниями и вариантом следующего эксперимента. |
| `experiments` | Дизайн, измеряемый исход, статус, результат, ограничения и источники. Итог может поддержать или ослабить гипотезу либо остаться неопределённым. |

1. При показе новых вариантов добавь записи `proposed`, если рабочую базу можно редактировать. При выборе или отказе обнови статус устойчивого ID и допиши в `feedback` дату, источник, решение и причину. Причина может быть `null`. [Пример отказа](templates/idea-feedback.json) служит шаблоном одной записи.
2. Перед повторной генерацией сопоставь отпечаток идеи с отклонёнными и опубликованными. Сохрани область запрета из слов автора. По явному пересмотру запиши `reopened` и верни идею в `proposed`. После публикации добавь ролик и известные публикации, затем укажи `published_video_id` и состояние `published`.
3. Для правки открой актуальную версию файла, обнови запись по ID и проверь изменения перед сохранением. При удалении идеи проверь сценарные пакеты, которые на неё ссылаются. При удалении видео удали его публикации и их снимки, очисти ссылки в идеях, наблюдениях, гипотезах и экспериментах. Запись с потерянными основаниями нужно пересмотреть или удалить. Проверяй уникальность ID в каждой коллекции и во всём наборе `publications`, существование связанных ID и порядок дат. JSON Schema проверяет форму отдельных записей.
4. В публичную базу добавляй общедоступные сведения и данные, разрешённые для публикации. Для приватной статистики используй локальную копию базы вне Git или согласованное приватное хранилище. При запуске генератора укажи путь к рабочей копии. Передай тот же путь сценаристу вместе с выбранной концепцией. При работе без записи подготовь изменение для переноса.

## Импорт статистики

Используй [CSV](templates/metrics.csv) или [JSON](templates/metrics.json). В JSON заполняется массив плоских строк с теми же названиями полей, что в CSV. Ручной ввод и ответы коннекторов преобразуй в этот формат. Для сохранения сначала нужен ID известной публикации из `published_videos[].publications`. Пустые поля, `null` и ноль различаются. Процентные значения используй по шкале, где `42.5` соответствует 42,5%. Средняя доля просмотра может превышать 100% при повторах.

Обязательные поля строки — `publication_id`, `captured_at`, `window`, `source` и хотя бы одна известная метрика. Снимок `lifetime` использует пустые границы периода. Для `fixed` нужны `window_start` и `window_end`, где начало предшествует концу, а конец не позже `captured_at`. Временные отметки для метрик используют RFC 3339 с часовым поясом. Поле `definitions` при необходимости описывает методику конкретных метрик как объект, пригодный для JSON, или JSON-объект внутри ячейки CSV.

Для скрипта нужен Python 3.9+ в Unix-среде. Из корня репозитория запусти предварительный просмотр. Для записи повтори команду с `--apply`.

```sh
python3 skills/video-idea-generator/scripts/channel_metrics.py \
  --database channel-experience/animations.json мой-экспорт.csv
```

Импорт объединяет совместимые значения по публикации, времени снимка и окну. Для подтверждённого исправления противоречащих значений используй `--replace-conflicts`. Детали сопоставления и разницы платформ описаны в [методике аналитики](../skills/video-idea-generator/references/analytics.md).
